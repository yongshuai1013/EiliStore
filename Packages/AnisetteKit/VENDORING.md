Local integration changes (not upstream claims):
- SwiftPM uses a locally built Unicorn XCFramework. The standard production project.yml supplies EILI_ON_DEVICE_ANISETTE and links this local package; remote remains the runtime default, with explicit user selection required for On-Device mode.
- Native initialization returns loader failures instead of aborting, validates setup operations, and catches C++ exceptions at Unicorn C entry points. Virtual allocator exhaustion returns a guest null allocation rather than aborting; this is not a guarantee against all malformed-library or memory-pressure failures.
- The reset API serializes VM destruction, closes guest host-file handles, and clears cached provisioning/library state after import or reset.
- Swift debug logging obeys the logging toggle. No production Anisette payload logging is enabled by this integration.

Build on macOS with Scripts/build-idevice-ios15.sh and Scripts/build-on-device-anisette.sh, then generate the standard app project with `xcodegen generate --spec project.yml`. Both project-on-device.yml and project-ios15-validation.yml are compatibility aliases for that same project. Scripts/prepare-anisette-ios15.sh is a compatibility entry point for building the canonical local dependency, not a second package override. The root local AnisetteKit dependency overrides SideSign's transitive dependency of the same identity; CI checks the actual native compile, active App Link Map symbol, and linked Unicorn archive.

Validation boundary: Linux contract tests and unsigned Apple archives do not establish successful provisioning/login or crash-free operation on iPhone 7 / iOS 15.8.5. The engine is included, but Apple ADI libraries are not bundled. The legacy execution path requires separately obtained trusted ARM64 libCoreADI.so and libstoreservicescore.so. Existing sessions retain their original mode.

Apple Music libstoreapi layout (including the user-provided 6.5.3 set)

- Recognized filenames: libstoreapi.so, libCoreADI.so, libCoreFP.so, libCoreLSKD.so, libFPDIFor3P.so. All five original filenames are required for import; mixed layouts, duplicate selections and renamed libstoreapi files are rejected without replacing a previously imported set.
- Import is for **offline diagnostics only**, not runtime support. The modern profile is explicitly gated off, even if synthetic metadata has no known static blockers. The UI reports incompatibility and disables selecting this unsupported layout. It does not silently switch an existing user preference or fall back from a selected local mode to remote.
- Before creating local identity, provisioning directories or a client, the service checks the profile and its bounded ELF metadata. The native entry also rejects a libstoreapi layout before allocating a VM. The existing legacy Android loader has incomplete hooks and returns zero for unknown imports; that fallback must never count as ABI compatibility.
- Static inspection of the user-provided five libraries closes their Apple DT_NEEDED dependencies and finds the six required ADI entrypoints in libstoreapi. It still finds 72 strong imports without explicit emulator implementations, including threading, TLS, file and Android runtime operations. Optional legacy destroy/dispose names are not treated as six required entrypoints. Resolving filenames alone is insufficient; no working modern provisioning/login is claimed.
- Run `bash Scripts/audit-adi-libraries.sh /private/path/to/five-libraries` on Linux/macOS with Swift 6 to inspect metadata only. Exit 1 means a known static blocker or unavailable runtime adapter; exit 2 means malformed/unreadable input or invalid invocation. JSON reports `runtime_verified: false`. No downloaded library, VM, Apple account, provisioning, signing or network operation is executed by this command.
- Source-only synthetic tests cover ELF bounds, profiles, dependency/symbol closure, modern import/blocking, no client/provider/identity creation, rename/mix rejection, remote routing and legacy restoration. The public repo/CI/IPA contains no user APK or Apple shared library. Redistribution permission remains unconfirmed.

SideStore-style runtime acquisition

- Settings exposes an explicit, confirmation-gated download from `https://zzz.haus/oda.json`. It accepts direct ODA metadata (`s`/`sha`/`sha256` with `l`/`libraries`/`payload`/`data`/`url`) containing inline Base64 ZIP or an HTTPS ZIP URL. This does not mirror SideStore's server-list discovery, automatic setup, or permissive hash-mismatch behavior.
- A valid SHA-256 is mandatory and mismatch is fatal. The hash and payload location come from the SAME third-party metadata: this is integrity checking, **not independently pinned authenticity**. The provider may change both. Source trust, legal availability and redistribution permission remain unverified; the UI discloses these boundaries before downloading.
- A cookie/credential/cache-free session bounds streamed metadata to 16 MiB and ZIP data to 64 MiB, rejects non-HTTPS URLs before requests and rejects HTTPS-to-HTTP redirects before following them. Redirects are limited to five. Only exact flat two-library or five-library regular-file sets are accepted; other paths, duplicates, symlinks and extras are rejected. Uncompressed data is capped at 64 MiB per file and 128 MiB total, with chunk limits, cancellation checks, explicit CRC comparison and bounded ELF64 LE/AArch64 shared-object headers.
- Downloads stage in a unique private directory and reuse the existing serialized import transaction/rollback. Network or validation failure and cancellation do not replace the installed cache; temporary payloads are removed. An active local login blocks download before networking. Successful installation resets the local engine cache, but does not select On-Device, provision, create an identity, contact Apple or modify remote credentials.
- Neither login nor read-only library status triggers retrieval. Remote Anisette remains the default. A downloaded modern five-library set is still diagnostic-only and blocked by the existing Android ABI gate; retrieval does not resolve the 72 unimplemented imports in the examined 6.5.3 set.
- `Tests/run-adi-download-tests.sh` exercises the downloader with generated synthetic ZIPs; `Tests/run-anisette-tests.sh` injects synthetic staging to check installation, cancellation, cleanup, mode isolation and the active-session guard. Test dependency downloads are source tooling only, never Apple binary downloads. No runtime-downloaded Apple binary is added to source, CI artifacts or the IPA.
- The downloader suite pins ZIPFoundation 0.9.19 and swift-crypto 3.0.0. On Linux only, its disposable dependency checkout receives two Swift 6/glibc compatibility edits (optional FILE pointer handling and unaligned scalar reads); no dependency is vendored or changed in production. On macOS the dependency is tested unmodified. Linux success is not a substitute for an Apple archive or real-device verification. Actual redirected HTTPS requests are not exercised by the URLProtocol mock suite; the pre-follow delegate guard is source-reviewed and its shared URL policy is unit-tested.
